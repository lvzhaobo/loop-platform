# FS-002 排序算法可视化后端服务 — 契约概览

> 一句话概述：  
为排序动画演示提供轻量级 REST API 后端，支持生成随机数组、计算冒泡排序步骤序列、实时控制动画状态（开始/暂停/继续/重置），并返回前端渲染所需的元数据。

## 核心交互流程
1. **页面初始化**：前端请求 `GET /api/meta` 获取标识 `Loop-20260723`，同时请求 `GET /api/array?size=20` 获得随机整数数组，绘制默认蓝色的条形图。
2. **启动排序**：用户点击“开始排序”按钮，前端发送 `POST /api/sort`（algorithm=bubble，附带当前数组），获取完整步骤序列，前端按 200ms/步的定时器消费步骤，根据 `type` 控制条形颜色（红-比较，橙-交换，绿-完成）。
3. **动画控制**：通过 `POST /api/sort/control` 发送 `pause`/`resume`/`reset` 命令，后端返回相应状态；前端据此暂停/继续定时器或清空步骤、重新绘制新数组。
4. **错误处理**：所有 API 遵循统一错误格式，前端以 Toast 展示用户友好提示。

## 建议的项目结构
- **后端（Flask）**：`app.py` 包含路由注册、参数校验、冒泡步骤生成器；`requirements.txt` 仅依赖 Flask。
- **前端**：`static/index.html` 使用原生 Canvas/DOM 绘制条形图，基于 `fetch` 调用 API，状态机实现（idle / sorting / paused / complete）。
- **配置**：无外部配置文件；颜色、动画间隔等可写在前端常量或从 `/api/meta` 的 `theme` 字段读取。

## 非目标（本服务不实现）
- 不支持冒泡以外的排序算法。
- 不包含用户认证、权限控制及数据持久化。
- 不提供 WebSocket 或 SSE 实时推送，动画由前端主动拉取步骤控制。
- 不做移动端深度优化，仅保证基本可用。
