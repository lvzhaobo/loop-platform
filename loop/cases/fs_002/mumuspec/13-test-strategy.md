# 测试策略 – 排序算法可视化网页 (FS-002)

## 1. 测试范围
验证后端 API 契约和前端用户故事的全部验收条件（AC‑001 至 AC‑008）。测试分为三个层次：
- **单元测试**：后端算法逻辑、参数校验。
- **接口/集成测试**：API 端点的输入输出、状态码、错误响应。
- **端到端测试 / 人工抽检**：前端 UI 行为、动画颜色、交互流程。

## 3. 自动化与人工分工

- **完全自动化（API 层）**：TC‑001, TC‑003, TC‑005‑API, TC‑006‑API, TC‑007‑API, TC‑008‑API。使用 Supertest 或 Postman/Newman 集合，集成到 CI 流水线。
- **人工抽检为主（UI 视觉/交互）**：TC‑002, TC‑004, TC‑005‑前端暂停确认, TC‑006‑前端继续确认, TC‑007‑前端重置确认, TC‑008‑前端显示确认。  
  *理由*：颜色渲染、动画平滑度等需要视觉确认；可采用 E2E 测试框架（Cypress/Playwright）辅助自动化断言（如检查元素 CSS 类、文本内容），但初始版本建议人工抽检为主，后续可逐步自动化。

## 4. 测试环境与数据
- 后端：Node.js 14+，模拟数据使用固定的数组以验证步骤可预测性（如 `[5,3,8,1]`）。
- 前端：Chrome/Firefox 最新版，屏幕分辨率 1920×1080。
- 测试数据准备：AC‑001 使用随机或固定 size；AC‑003 提供固定小数组；AC‑007 验证重置后数组变化。

## 5. 缺陷跟踪
任何测试用例失败均记录在项目缺陷管理工具，关联对应 AC，修复后重新执行相关 TC 并进行回归。
