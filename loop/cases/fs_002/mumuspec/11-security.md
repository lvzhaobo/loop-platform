# 安全设计 – FS-002

## 1. 认证与授权
- 本应用面向单用户本地演示，**不实现用户认证**。
- 前后端通信仅限本地 `127.0.0.1`，若需局域网访问，由网络防火墙或 Flask 绑定地址控制。
- 不涉及角色或权限，无授权机制。

## 2. 数据保护
### 2.1 输入校验
- **参数类型与范围**：所有 API 入参（路由参数、查询字符串、请求体）均进行严格校验：
  - `size` / `resetSize`：必须为整数，范围 5‑50。
  - `algorithm`：白名单匹配，仅允许 `"bubble"`。
  - `array`：必须是整数数组，长度 ≥ 2，元素值 1‑100。
  - `command`：白名单匹配 `pause` / `resume` / `reset`。
- **JSON 解析安全**：使用 Flask 内置 `request.get_json()`，依赖标准库 `json`，防止注入。
- **拒绝无效请求**：返回 400 及明确错误码，不泄露堆栈信息。

### 2.2 输出编码
- 所有响应为 `application/json`，无需 HTML 实体编码，前端直接使用 JSON。
- 前端从 DOM 操作渲染文本（如 `identifier`）时，使用 `textContent` 而非 `innerHTML`，避免 XSS。

### 2.3 数据最小化
- 不存储或传输任何个人信息、Session、Cookie。
- 排序数组为随机生成，无业务关联。

### 2.4 配置文件安全
- `config.json` 只读，禁止用户通过 API 修改。
- 服务以低权限用户运行，禁止文件系统其他写操作。

## 3. 代码安全
- **禁止 `eval()` / `exec()`**：后端及前端均不使用动态代码执行。
- **依赖管理**：仅使用 Flask 及其依赖，定期检查已知漏洞。
- **异常处理**：全局捕获，避免敏感信息通过 500 响应泄露。

## 4. 资源与可用性防护
- 限制数组最大长度（50），防止排序步骤爆炸（冒泡最坏 1225 步），避免 CPU 长时间占用。
- 单次请求处理时间上限：若超过 500ms，主动终止并返回 500。
- 拒绝超大请求体：Flask 默认限制 1MB，足以处理最大数组。

## 5. 安全红线
| 红线 | 描述 | 后果 |
|------|------|------|
| 未校验用户输入直接用于计算 | 可能导致 DoS 或异常 | 必须每接口严格校验 |
| 响应中泄露服务器路径或异常堆栈 | 信息泄露 | 500 错误统一格式，关闭 Flask debug 模式在生产环境 |
| 前端使用 `innerHTML` 渲染后端返回文本 | XSS 风险 | 必须用 `textContent` 或转义 |
| 允许任意 `algorithm` 字符串 | 可能执行未知代码 | 白名单控制 |
| 忽略速率限制（如需要） | 演示环境可接受，但需意识 | 可后续增加 Flask-Limiter |

## 6. 安全测试建议
- 模糊测试：发送异常 `size`、`command`、缺失字段，验证返回 400 且服务不崩溃。
- 并发测试：快速连续点击开始/暂停/重置，确保前端状态机不混乱。
