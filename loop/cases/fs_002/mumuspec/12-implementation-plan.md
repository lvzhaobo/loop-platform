# 实施计划 – 排序算法可视化网页 (FS-002)

## 1. 项目范围
基于用户故事 US‑001 至 US‑005 和 REST API 契约，交付一个完整的冒泡排序可视化网页，包含后端 API 服务和单个 HTML 前端。后端使用 Node.js/Express（或其他轻量框架），前端使用原生 JavaScript、HTML、CSS。

## 2. 里程碑与交付物

| 里程碑 | 主要交付物 | 完成标准 |
|--------|------------|----------|
| M1 – API 开发完成 | 后端服务代码，4 个端点全部实现并自测通过 | 所有端点符合 API 契约，通过单元测试和接口测试 |
| M2 – 前端开发完成 | 单个 HTML 文件，包含条形图渲染和控制界面 | 前端可独立调用 API 并展示初始数组，具备开始、暂停、继续、重置按钮 |
| M3 – 集成测试通过 | 自动化测试套件 + 人工抽检报告 | 所有验收条件（AC‑001 至 AC‑008）通过，前后端联调无阻塞问题 |
| M4 – 上线部署 | 生产环境部署配置，演示 URL | 线上环境稳定运行，标识文字正确展示 |

## 3. 时间线

| 阶段 | 工作内容 | 工期 | 起止（示例） |

## 4. 关键任务分解

- **后端**  
  - 项目脚手架搭建（Express + CORS）  
  - 实现数组生成逻辑（随机、无重）  
  - 实现冒泡排序步骤生成器  
  - 实现状态控制（内存存储当前步骤指针）  
  - 错误处理中间件  
  - 单元测试覆盖（Jest/Mocha）

- **前端**  
  - 基础 HTML 结构：标题（含标识）、画布/div 容器、控制栏  
  - CSS 样式：条形颜色定义、按钮布局  
  - JavaScript 核心：  
    - API 调用封装（`api.js`）  
    - 条形图绘制与更新函数  
    - 动画循环（消费 `steps`，支持暂停/继续）  
    - 事件绑定与状态管理  
  - 与后端联调，确认字段名一致

- **测试**  
  - API 自动化测试（Postman/Newman 或 Supertest）  
  - 前端 E2E 测试（Cypress/Playwright）覆盖关键交互路径  
  - 人工检查：动画颜色变化流畅度、标识文字显示、响应式适配（若需要）

- **部署**  
  - 配置静态文件服务，提供前后端一体部署（如 Node.js 托管 HTML）  
  - 健康检查与监控

## 5. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 动画性能不佳（大量条形） | 用户体验卡顿 | 限制数组大小 ≤ 50，使用 requestAnimationFrame |
| 状态管理复杂导致暂停/重置 Bug | 动画紊乱 | 后端提供强一致性的步骤序列，前端仅按索引播放 |
| API 错误处理遗漏 | 前端异常 | 编写全面的错误处理测试用例 |
| 浏览器兼容性 | 特定浏览器渲染异常 | 使用标准 CSS Flexbox/Canvas，减少依赖 |

## 6. 验收准则
所有验收条件（AC‑001 至 AC‑008）必须 100% 通过，由测试策略（13‑test‑strategy.md）中定义的测试用例覆盖证明。
