# 非功能需求 (NFR) – 排序算法可视化网页 FS-002

## 1. 性能
| 指标 | 目标 | 说明 |
|------|------|------|
| API 响应时间 (P95) | < 200ms | 对于生成数组、排序步骤计算，在本地单线程 Flask 下需保证低延迟。 |
| 前端动画帧间隔 | 可配置，默认 200ms/步 | 使用 `setTimeout` 调度，保证动画流畅无卡顿。 |
| 页面加载时间 | < 1s | 首次加载 meta + array 两个请求总时间不超过 1s，条形图渲染需在 100ms 内完成。 |
| 最大数组长度 | 50 | 数组规模限制避免排序步骤爆炸（最多约 1225 步冒泡），保证服务端计算 < 50ms。 |

## 2. 可用性
| 指标 | 目标 | 说明 |
|------|------|------|
| 系统可用性 | 演示环境 100%（单用户） | 服务运行于开发机，无冗余，但需保证代码健壮性，不会因异常输入崩溃。 |
| 错误处理 | 用户友好提示 | API 错误返回清晰错误码和消息，前端必须捕获并显示，避免白屏。 |
| 浏览器兼容 | 现代浏览器（Chrome/Firefox/Edge 最新版） | 使用原生 HTML/CSS/JS，无框架依赖，支持 ES6 `fetch` 和 `DOM` 操作。 |
| 移动端适配 | 基本可用 | 条形图可横向滚动或按比例缩放，按钮尺寸适配触屏。 |

## 3. 安全性
（详见 11‑security.md，此处为高层指标）
| 指标 | 要求 |
|------|------|
| 输入校验 | 所有 API 参数进行严格类型和范围校验，拒绝无效输入。 |
| 无认证 | 内网演示，不实现用户认证，但接口不接受外部不可信调用（由网络隔离保证）。 |
| 注入防护 | 使用 Flask 内置 JSON 解析，不拼接 SQL/命令；禁止 `eval` 等危险函数。 |
| 数据暴露 | 不传输个人或敏感数据；响应仅包含数组、步骤等演示数据。 |
| 资源限制 | 限制数组大小 5‑50，防止消耗大量内存或 CPU。 |

## 4. 可维护性
- 后端代码模块化：路由、步骤生成、工具函数分离。
- 前端代码清晰注释，状态管理使用确定的状态机（idle / sorting / paused / complete）。
- API 契约驱动开发，杜绝前后端字段不一致。
