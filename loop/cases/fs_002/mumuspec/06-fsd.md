# 功能规格说明 (FSD) – 排序算法可视化网页 FS-002

## 1. 功能清单
| 模块 | 功能 | 对应 API | 用户故事 | 说明 |
|------|------|---------|----------|------|
| 初始展示 | 加载并绘制初始随机条形图 | `GET /api/array` | US‑001 | 页面打开后自动获取数组，所有条形默认为蓝色（#3498db），无特殊颜色标识。 |
| 排序动画 | 发送排序请求，获得步骤序列并逐帧播放 | `POST /api/sort` | US‑002 | 只支持冒泡排序；步骤包括比较（红）、交换（橙）、完成（绿）；前端按时序更新条形颜色与位置。 |
| 动画控制 | 暂停排序播放 | `POST /api/sort/control {"command":"pause"}` | US‑003 | 暂停动画后状态变为 paused，可恢复。 |

| 动画控制 | 重置到初始状态 | `POST /api/sort/control {"command":"reset"}` | US‑004 | 终止当前动画，返回新随机数组并重绘，所有颜色恢复蓝色。 |
| 页面标识 | 固定展示“Loop‑20260723” | `GET /api/meta` | US‑005 | 页面显眼位置渲染该字符串，确保可见且不被遮挡。 |

## 2. 交互流程

### 2.1 页面加载
1. 浏览器发起 `GET /api/meta`，获取 `identifier`，将“Loop‑20260723”显示在页面标题或固定区域。
2. 发起 `GET /api/array?size=20`，获取 `values`，使用 `<canvas>` 或 `<div>` 绘制条形图，所有条形为默认蓝色。

### 2.2 开始排序
1. 用户点击 **“开始排序”** 按钮。
2. 前端从条形图当前数组构造 `array` 字段，调用 `POST /api/sort`，algorithm 固定为 `"bubble"`。
3. 若成功，收到 `steps` 数组，前端启动定时器（例如每 200ms 一步）消费步骤：
   - `compare`：将对应索引的条形变为红色，短暂停留后恢复（或保留至下一步）。
   - `swap`：交换两索引的条形位置，过程中变为橙色，完成后恢复颜色。
   - `complete`：将所有条形变为绿色，动画结束。
4. 定时器运行中，可响应暂停/继续/重置操作。

### 2.3 暂停与继续
1. 点击 **“暂停”** 按钮，前端发送 `POST /api/sort/control {"command":"pause"}`。
2. 收到 `status: "paused"`，前端清除定时器，停止步骤消费。
3. 点击 **“继续”** 按钮，发送 `{"command":"resume"}`，收到 `status: "running"` 后重启定时器，从当前步骤继续。

### 2.4 重置
1. 点击 **“重置”** 按钮，发送 `POST /api/sort/control {"command":"reset"}`。
2. 收到 `status: "reset"` 和新的 `values`，前端立即清除定时器、清空步骤队列，用新数组重绘条形图，所有条形恢复蓝色。

### 2.5 异常反馈
- 若 API 返回业务错误（400/500），前端在页面以 Toast 或提示框显示错误消息（来自 `error.message`），不中断用户操作。
- 网络异常时提示“网络错误，请刷新重试”。

## 3. 页面布局建议
- 顶部居中：⏸️“开始排序” 🔄“暂停” ▶️“继续” 🔃“重置”
- 标识文字“Loop‑20260723”展示于标题栏或正上方醒目位置，颜色与背景形成对比。
- 条形图占据主体空间，每个条形宽度均匀，标注索引或数值可选。
