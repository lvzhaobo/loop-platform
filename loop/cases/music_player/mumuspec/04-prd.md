# 产品需求文档（PRD）– 音乐播放器 v1.0

## 1. 功能范围

### 1.1 播放控制
- **播放/暂停**：提供明显的播放/暂停按钮，点击后切换状态；切换有即时反馈（图标变化），且音频响应延迟≤100ms。
- **上一首/下一首**：基于当前的“播放列表”顺序切换曲目；若无上一首/下一首，按钮禁用或静默不响应；切换时应有短暂视觉提示（如列表高亮变化）。
- 行为细节：当播放结束时，自动按顺序播放下一首；若为列表最后一首，停止或循环取决于播放模式，V1 默认顺序播放，不执行循环。

### 1.2 进度条拖拽
- 进度条全长表示当前曲目总时长，已播放区域以高亮颜色表示。
- 鼠标/手指拖拽滑块可改变播放位置；拖拽过程中音频暂停更新或实时跟随（选择实时预览）。释放滑块后立即从新位置继续播放。
- 进度条旁应显示当前时间与总时长（格式 mm:ss）。
- 支持点击进度条任意位置跳转（非滑块拖拽方式）。
- 性能要求：拖拽时 UI 帧率保持≥55fps，滑块位置与音频时间同步误差<200ms。

### 1.3 音量调节
- 独立的音量滑块，控制播放器输出音量（应用内增益），不改变系统全局音量。
- 默认音量 80%；可静音/取消静音（图标切换）。
- 滑块范围 0-100，步长为 1；支持滚轮或方向键微调。
- 当前音量值可在滑块附近显示，或通过 tooltip 展示。

### 1.4 深色主题界面
- 基础配色方案：背景色 #121212（或更深的灰），表面/卡片 #1E1E1E，主操作色（如播放按钮）采用有活力的亮色但不过于刺眼（如 #1DB954 绿色）。
- 文字与图标与背景对比度至少 4.5:1（WCAG AA）。
- 按钮、滑块、列表项等所有 UI 组件统一深色风格，无亮色闪烁。
- 支持窗口缩放时的布局自适应；按钮与控件不重叠，文本清晰无截断。

### 1.5 播放列表与文件管理
- 应用启动时自动扫描用户指定的音乐文件夹（或默认系统音乐目录）；若无音乐文件，界面显示空状态提示“暂无音乐，请添加文件/文件夹”。
- 支持拖放音频文件或文件夹到窗口进行添加。
- 播放列表视图：显示文件名（或元数据标题）、艺术家、时长；当前播放曲目高亮。
- 支持双击曲目直接播放；点击后更新播放状态。
- 对不支持格式或损坏文件：跳过并给出提示“文件无法播放（损坏或格式不支持）”。

### 1.6 键盘交互与无障碍
- 预设快捷键：
  - 空格：播放/暂停
  - ←/→：快退/快进 5 秒（或上一首/下一首 Alt+左/右）
  - ↑/↓：增加/减少音量 5%
  - Tab 键：正常焦点顺序，所有交互元素有可见焦点轮廓。
- 所有按钮具备 aria-label 或等效的可访问名称（若为 Web），确保屏幕阅读器可用。

### 1.7 错误与边界状态处理
- 无音频设备或音频设备被占用：提示“音频设备不可用，请检查设备连接”。
- 文件权限不足：提示“无法访问音乐文件夹，请检查权限设置”。
- 应用进入后台（移动端或系统休眠）：音频正常播放，保持后台播放能力（若平台支持）。

## 2. 用户流程

### 2.1 主流程：首次使用与播放
1. 用户启动应用。
2. 应用检测默认音乐目录为空或未配置，展示“添加音乐”引导页。
3. 用户点击“添加文件夹”或拖入音频文件。
4. 应用解析文件并生成播放列表，显示第一首曲目信息。
5. 用户点击播放按钮（或双击曲目），开始播放。
6. 播放过程中，进度条自动推移；用户可随时操作进度、音量、切歌。
7. 曲目结束时，自动播放下一首；若为最后一首，停止播放并恢复第一首等待手动操作。

### 2.2 异常流程：损坏文件处理
1. 扫描文件夹时，解析到损坏文件。
2. 该文件不被加入播放列表，界面显示一条可关闭的提示：“1 个文件无法识别，已跳过”。
3. 若播放列表中某个文件在播放时发现损坏（解码失败），自动跳到下一首并提示：“当前文件无法播放，已切换到下一首”。

### 2.3 搜索与高级操作（V1 范围外，预留）
- 搜索、播放模式切换（随机/循环）、均衡器等将在后续版本考虑，当前只需在设计上留出可扩展区域，不影响简洁性。

## 3. 验收条件

### 3.1 功能验收

| 功能项 | 验收条件 |
|--------|----------|
| 播放/暂停 | 1. 点击播放按钮，音频开始播放，图标变为暂停；按钮有合适的动效。<br>2. 再次点击，音频暂停，图标恢复为播放。<br>3. 音频文件尾自动切换到下一首（若存在）。<br>4. 从点击到声音输出的延迟<100ms。 |
| 上一首/下一首 | 1. 点击下一首按钮，播放下一个列表项，界面更新当前曲目高亮。<br>2. 点击上一首，播放上一个曲目；若当前为第一首，则按钮禁用或在 UI 上表明无操作（不崩溃）。<br>3. 切换过程无杂音、无缝（或极小间隙）。 |
| 进度条拖拽 | 1. 拖动进度滑块时，时间显示实时变化。<br>2. 释放滑块后，音频从对应位置继续播放，误差<200ms。<br>3. 点击进度条空白区域，滑块跳至该位置并播放。<br>4. 拖拽期间 UI 帧率稳定（可用 FPS 工具验证，不低于 55fps）。 |
| 音量调节 | 1. 拖动音量滑块，播放器输出音量线性变化，系统音量不受影响（若有系统音量对比）。<br>2. 点击静音图标，音量降至 0，图标切换；再次点击恢复原音量。<br>3. 滑块最小值=0，最大值=100，默认值=80。 |
| 深色主题 | 1. 所有界面组件背景色符合设计规范（#121212 等）。<br>2. 文字与背景对比度≥4.5:1（使用对比度检查工具验证）。<br>3. 窗口缩放至最小分辨率 800x600 时，界面无重叠、无横向滚动条，核心按钮可见。 |
| 播放列表 | 1. 添加文件夹后，列表显示所有支持的音频文件（按文件名排序）。<br>2. 当前播放曲目高亮显示（背景色或指示图标）。<br>3. 双击某曲目，立即切换播放。<br>4. 无音乐时显示空状态提示，并提示如何添加。 |
| 错误处理 | 1. 选择空文件夹：不崩溃，提示“未找到可播放的音乐文件”。<br>2. 拖入非音频文件：不添加，可静默忽略或提示。<br>3. 播放中断文件：自动跳过，并给出提示。 |
| 键盘与无障碍 | 1. 按空格键，播放/暂停状态切换（UI 同步）。<br>2. 方向键控制音量与快进（按设计），可配置或固定。<br>3. Tab 键焦点顺序符合逻辑，焦点状态明显可见。 |

### 3.2 非功能验收
- **性能**：使用性能监控工具验证冷启动时间（≤1.5s）、内存占用（后台播放时 < 100MB）、CPU 占用（播放时 < 10%）。
- **兼容性**：在目标平台（例如 Windows 10/11, macOS 12+, 或 Chrome/Firefox 最新版）上完成全功能跑测，无布局错乱或功能偏差。
- **稳定性**：连续播放 2 小时无崩溃；随机操作 100 次无异常退出。
- **错误日志**：出现异常时有日志记录（若适用），便于排查，但不影响终端用户体验。
