# 用户故事 – 音乐播放器 v1.0

## US-01: 基础播放控制（播放/暂停/上一首/下一首）
**作为** 音乐爱好者  
**我想** 通过按钮控制音乐的播放、暂停以及切换曲目  
**以便** 流畅地享受播放列表中的音乐

### 验收标准（AC）
- **AC-001** 点击播放按钮后，音频开始播放，播放按钮图标变为暂停图标；前端需展示暂停图标且播放状态指示为“播放中”。
- **AC-002** 点击暂停按钮后，音频暂停，图标恢复为播放图标；前端展示播放图标且播放状态为“已暂停”。
- **AC-003** 当前曲目自然播放结束后，系统自动切换到下一首曲目（若存在）；若为最后一首则停止播放并等待用户操作。
- **AC-004** 点击下一首按钮，立即切换到播放列表中的下一曲目，界面高亮更新为新曲目；若当前为最后一首则按钮禁用或不产生操作（不崩溃）。
- **AC-005** 点击上一首按钮，立即切换到上一曲目；若当前为第一首则按钮禁用或不产生操作。
- **AC-006** 切换曲目过程无杂音，播放过渡流畅（间隙极小）。
- **AC-007** 从点击播放到声音输出延迟 < 100ms。
- **AC-008** 空格键触发播放/暂停，功能与按钮一致，UI 同步更新。

### 对应的 API 可观测断言
- AC-001 → `POST /api/playback/play` 返回 `200`，响应体 `status` 字段为 `"playing"`。
- AC-002 → `POST /api/playback/pause` 返回 `200`，`status` 为 `"paused"`。
- AC-003 → 播放结束后前端请求 `POST /api/playback/next`；若存在下一首返回 `200` 及新曲目信息；若无下一首返回 `404`，错误码 `NO_NEXT_TRACK`。
- AC-004 → `POST /api/playback/next` 返回 `200`，`currentTrackId` 变化为下一首 ID；若为最后一首返回 `404`，错误码 `NO_NEXT_TRACK`，前端禁用按钮。
- AC-005 → `POST /api/playback/previous` 返回 `200`，`currentTrackId` 变化为上一首 ID；若为第一首返回 `404`，错误码 `NO_PREVIOUS_TRACK`。
- AC-006 → 无直接 API 断言；但切换响应迅速（延迟在客户端处理），API 调用成功即表示后端准备就绪。
- AC-007 → `POST /api/playback/play` 响应时间 < 100ms，可通过性能监控验证。
- AC-008 → 前端按空格时调用对应 API（play 或 pause），响应字段 `status` 与 UI 一致。

## US-02: 进度条拖拽与跳转
**作为** 用户  
**我想** 拖拽进度条或点击进度条任意位置来改变播放位置  
**以便** 快速定位到歌曲中想听的部分

### 验收标准（AC）
- **AC-009** 拖动进度滑块时，当前时间显示实时变化，且与滑块位置同步。
- **AC-010** 释放滑块后，音频从新位置继续播放，音频播放位置与滑块设定位置的误差 < 200ms。
- **AC-011** 点击进度条空白区域，滑块跳至该位置并立即从该位置播放，音频时间与点击位置同步。
- **AC-012** 进度条旁显示当前时间与总时长，格式 `mm:ss`。
- **AC-013** 拖拽期间 UI 帧率 ≥ 55 fps，滑块位置与音频时间同步误差 < 200ms。

### 对应的 API 可观测断言
- AC-009 → 前端在拖拽过程中可调用 `GET /api/playback/state` 获取 `currentTime`，或拖拽结束时调用 `POST /api/playback/seek` 更新。释放时调用 seek 后响应包含 `currentTime`，前端据此更新显示。
- AC-010 → `POST /api/playback/seek` 请求体 `{ "position": 30.5 }`，响应 `200`，`currentTime` 与请求的 `position` 差值 < 0.2 秒。
- AC-011 → 同 seek 接口，点击位置转换为 `position` 值，调用后响应 `200`，`currentTime` 与点击位置一致。
- AC-012 → `GET /api/playback/state` 返回 `currentTime`（秒）和 `duration`（秒），前端自行格式化为 `mm:ss`。
- AC-013 → 性能指标由前端实现，但 API 响应需在 50ms 内完成以保证流畅。

## US-03: 音量调节与静音
**作为** 用户  
**我想** 通过滑块调节播放器的音量，并可一键静音/取消静音  
**以便** 控制播放音量而不影响系统其他音量

### 验收标准（AC）
- **AC-014** 拖动音量滑块时，播放器输出音量线性变化，系统全局音量不变。
- **AC-015** 滑块范围 0-100，步长 1，默认值为 80。
- **AC-016** 点击静音图标后，音量降为 0，图标切换为静音态；再次点击恢复至静音前的音量。
- **AC-017** 使用键盘方向键（↑/↓）可微调音量，每按一次增减 5%。
- **AC-018** 当前音量值在滑块附近显示（或通过 tooltip）。

### 对应的 API 可观测断言
- AC-014 → `POST /api/playback/volume` 请求 `{ "level": 45 }`，返回 `200`，`volume` 字段为 `45`，系统音量不受影响。
- AC-015 → `GET /api/playback/state` 初始 `volume` 为 `80`；`POST` 设置音量后返回的 `volume` 在 0-100 范围。
- AC-016 → `POST /api/playback/toggleMute`（无请求体），返回 `200`，`muted` 字段为 `true` 且 `volume` 为 `0`；再次调用返回 `muted: false`，`volume` 恢复为之前值。
- AC-017 → 方向键触发多次 `POST /api/playback/volume`，每次增减 5，可通过查看 `volume` 字段变化验证。
- AC-018 → `GET /api/playback/state` 返回 `volume`，前端据此展示。

## US-04: 播放列表与文件管理
**作为** 用户  
**我想** 能够扫描本地音乐文件夹、拖放添加文件，并直观查看播放列表  
**以便** 轻松管理我的音乐库并快速选择播放

### 验收标准（AC）
- **AC-019** 应用启动时自动扫描默认音乐目录，若无音乐文件，界面显示空状态提示“暂无音乐，请添加文件/文件夹”。
- **AC-020** 通过 UI 添加文件夹后，列表显示所有支持的音频文件（按文件名排序）。
- **AC-021** 支持拖放音频文件或文件夹到窗口，文件被添加至播放列表，不支持格式静默忽略或提示。
- **AC-022** 播放列表视图显示文件名（或元数据标题）、艺术家、时长；当前播放曲目高亮显示。
- **AC-023** 双击某曲目，立即切换播放该曲目，播放状态更新。
- **AC-024** 对不支持格式或损坏文件：扫描时跳过并给出提示“文件无法播放（损坏或格式不支持）”；播放时遇到损坏文件自动跳到下一首并提示。

### 对应的 API 可观测断言
- AC-019 → `GET /api/library/playlist` 返回 `200`，`tracks` 数组为空，前端展示空状态。
- AC-020 → `POST /api/library/scan` 请求 `{ "path": "/music" }`，返回 `200`，响应包含 `addedTracks` 数组，列出所有支持文件的信息（`id`, `title`, `artist`, `duration`, `format`）。
- AC-021 → `POST /api/library/playlist/add` 传入文件路径列表，返回 `200`，`addedTracks` 包含成功添加的文件，`skippedFiles` 包含不支持或无法添加的文件及原因；前端根据 `skippedFiles` 提示。
- AC-022 → `GET /api/library/playlist` 返回的每个 track 对象有 `title`、`artist`、`duration`；前端负责高亮当前播放曲目，可通过 `GET /api/playback/state` 获得 `currentTrackId` 进行比较。
- AC-023 → `POST /api/playback/play` 请求体 `{ "trackId": "123" }`，返回 `200` 且 `currentTrackId` 为 `"123"`，状态为 `"playing"`。
- AC-024 → 扫描时 `POST /api/library/scan` 返回的 `skippedFiles` 中包含原因 `CORRUPTED_FILE` 或 `UNSUPPORTED_FORMAT`；播放时若解码失败，返回 `500` 错误码 `TRACK_UNPLAYABLE`，前端据此跳转和信息提示。

## US-05: 深色主题与界面适配
**作为** 用户  
**我想** 使用深色主题的应用界面，且在窗口缩放时保持良好的布局  
**以便** 在暗光环境下获得舒适的视觉体验

### 验收标准（AC）
- **AC-025** 界面背景色为 `#121212`，卡片/表面色为 `#1E1E1E`，主操作色为 `#1DB954`，无亮色闪烁。
- **AC-026** 文字与图标对比度至少 4.5:1（WCAG AA）。
- **AC-027** 窗口缩放至最小分辨率 800×600 时，界面无重叠、无横向滚动条，核心按钮可见。
- **AC-028** 主题配置持久化，重启应用后仍为深色主题。

### 对应的 API 可观测断言
- AC-025 → `GET /api/settings` 返回 `theme` 字段值为 `"dark"`，前端据此应用 CSS 变量。
- AC-026 → 无直接 API 断言，但 `theme` 字段可触发高对比度模式标记，间接确保设计系统遵循对比度。
- AC-027 → 纯前端布局，不涉及 API。
- AC-028 → `GET /api/settings` 返回一致的 `theme: "dark"`；可提供 `POST /api/settings/theme` 保存主题，重启后 `GET` 返回同样值。

## US-06: 错误与边界状态处理
**作为** 用户  
**我想** 在遇到异常（如音频设备不可用、文件权限不足、文件损坏）时收到明确提示  
**以便** 了解问题并采取相应措施，不影响整体使用

### 验收标准（AC）
- **AC-029** 无音频设备或设备被占用时，播放操作提示“音频设备不可用，请检查设备连接”。
- **AC-030** 文件权限不足（如无法读取音乐文件夹）时，提示“无法访问音乐文件夹，请检查权限设置”。
- **AC-031** 播放过程中遇到损坏文件，自动跳到下一首并提示“当前文件无法播放，已切换到下一首”。
- **AC-032** 应用进入后台时，音频保持正常播放（若平台支持），无崩溃或异常停止。
- **AC-033** 连续运行 2 小时或随机操作 100 次无崩溃。

### 对应的 API 可观测断言
- AC-029 → `POST /api/playback/play` 或其他播放操作返回 `503`，错误码 `AUDIO_DEVICE_UNAVAILABLE`，消息包含“音频设备不可用”。
- AC-030 → `POST /api/library/scan` 返回 `403`，错误码 `PERMISSION_DENIED`，消息“无法访问音乐文件夹，请检查权限设置”。
- AC-031 → 播放时如遇损坏文件，返回 `500` 错误码 `TRACK_UNPLAYABLE`，消息“当前文件无法播放，已切换到下一首”，前端自动请求 `POST /api/playback/next` 跳转。
- AC-032 → 所有 API 在后台状态依然可用，无超时或中断；客户端可通过周期性 `GET /api/playback/state` 验证。
- AC-033 → 稳定性通过自动化测试保证，API 无内存泄漏或崩溃；可通过监控 API 健康检查 `GET /api/health` 长期返回 `200`。
