## 2. 交互流程

### 2.1 基础播放流程
1. 用户点击播放按钮（或空格键） → 前端调用 `POST /api/playback/play`；
2. 后端更新播放状态为 `playing`，返回当前状态；
3. 前端展示暂停图标，状态文字“播放中”；
4. 再次点击则调用 `POST /api/playback/pause`，状态变为 `paused`，图标恢复。

### 2.2 曲目切换流程
- **下一首**：用户点击“下一首”或当前曲目结束 → 前端调用 `POST /api/playback/next`；
  - 成功：后端返回新曲目信息，前端更新高亮并播放；
  - 无下一首：后端返回 `404`，前端禁用按钮。
- **上一首**：类似流程，调用 `POST /api/playback/previous`。

### 2.3 进度跳转流程
1. 用户拖拽进度滑块或点击进度条 → 前端计算目标时间位置；
2. 释放滑块（或点击）时调用 `POST /api/playback/seek { position }`；
3. 后端调整播放位置，返回 `currentTime`；
4. 前端更新显示时间，误差小于200ms。

### 2.4 音量调节流程
1. 拖动音量滑块或按方向键 → 前端调用 `POST /api/playback/volume { level }`；
2. 后端设置音量，返回新音量值；
3. 点击静音图标 → 调用 `POST /api/playback/toggleMute`；
   - 静音时 `muted: true, volume: 0`，再次点击恢复原音量。

### 2.5 文件管理流程
- **启动扫描**：应用启动 → 调用 `GET /api/library/playlist`；若为空，调用 `POST /api/library/scan`（使用默认目录）；
- **手动添加文件夹**：用户选择文件夹 → 调用 `POST /api/library/scan { path }` → 返回新增 track 列表及跳过信息；
- **拖放添加**：用户拖放文件/文件夹 → 前端提取路径调用 `POST /api/library/playlist/add` → 更新播放列表。

### 2.6 双击播放流程
用户双击播放列表项目 → 获取该 track ID → 调用 `POST /api/playback/play { trackId }` → 更新播放状态，曲目高亮。

### 2.7 异常处理流程
- **音频设备不可用**：任何播放请求可能返回 `503`，前端展示“音频设备不可用”并禁用播放按钮；
- **权限不足**：扫描请求返回 `403`，提示“无法访问音乐文件夹”；
- **播放损坏文件**：后端播放失败返回 `500 TRACK_UNPLAYABLE`，前端自动调用 `POST /api/playback/next` 并提示用户。
