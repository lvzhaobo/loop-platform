# 安全设计

## 1. 认证与授权
- 应用定位为本地单用户音乐播放器，无用户系统，不实施认证与授权。
- 所有 API 仅通过本地浏览器访问，Flask 启动时绑定 `127.0.0.1`，不暴露于网络。

## 2. 文件访问安全

### 2.1 沙箱原则
音乐库操作（扫描、添加文件、获取文件路径）限制在一个或多个预先配置的“音乐根目录”内。配置文件 `config.yaml` 中指定：
```yaml
music_roots:
  - /home/user/Music
  - /media/external_drive/Music
```

### 2.2 路径遍历防护
所有接收文件路径或文件夹路径的参数必须经过安全净化：
- 将用户输入路径解析为绝对路径；
- 检查绝对路径是否以任一音乐根目录为前缀；
- 拒绝包含 `..` 或符号链接跳出允许范围的路径；
- 返回 `403 Forbidden`，错误码 `PATH_TRAVERSAL_DETECTED`。

### 2.3 符号链接处理
- 扫描文件夹时，若使用 `os.walk` 遇符号链接，默认不跟随，或需验证目标在允许范围内才可跟随（谨慎开启）。

## 3. 输入校验
所有 API 输入必须严格校验：
- `trackId`：符合 UUID 格式；
- `position`（seek）：非负浮点数，不超过曲目时长；
- `volume`：整数，0-100；
- `path`：字符串长度 ≤ 4096，仅允许合法的文件系统字符；
- 多文件添加时，限制数组长度 ≤ 5000。

任何校验失败返回 `400 Bad Request`，错误码 `VALIDATION_ERROR`，详细说明。

## 4. 数据保护
- 配置文件和 JSON 数据文件存储在 `data/` 目录，权限设置为仅所有者可读写（`600`）。
- 日志中不记录完整文件路径（仅记录相对于音乐根目录的路径）或敏感信息。
- 错误响应不返回堆栈跟踪或系统内部路径（生产模式）。

## 5. 依赖安全
- 使用 `pip freeze` 并定期审查 Flask、Werkzeug 等依赖是否有已知漏洞（可通过 safety 或 bandit）。
- 开发中启用 Flask 调试模式需谨慎，生产部署务必关闭 `debug=True`。

## 6. 安全红线
- **绝对禁止**通过 API 读取或写入配置的音乐根目录之外的任何文件。
- **绝对禁止**API 执行系统命令或任意文件删除。
- **绝对禁止**在错误消息中暴露绝对文件路径、系统用户名等敏感信息。
- **绝对禁止**允许从客户端指定根目录路径（必须通过服务端配置文件设定）。

## 7. 审计与日志
- 记录所有文件操作（扫描、添加）和播放控制操作，包含时间、请求来源（localhost）、操作结果，便于审计。
- 错误日志记录异常类型，但屏蔽详细堆栈（生产环境）。
