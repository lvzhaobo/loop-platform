# 生成任务:单页交互式工具(Spec 形态)

你是资深全栈工程师。请按下方「需求规格」与「验收标准」,生成一个**可直接运行的单页交互式 Web 工具**。
这不是内容列表站:**不要**做「列表页 + 详情页 + 数据集」那套,不要 data/*.json 图鉴,不要 list_marker/detail_markers。
它是一个围绕**核心交互**(计时、计算、编辑、绘制、播放等)的工具,交互逻辑主要在浏览器端。

## 技术栈与结构
- 后端:Flask(Python),入口 `app.py`,监听 `PORT` 环境变量(默认 5000),`host="0.0.0.0"`。
- 后端职责通常很薄:渲染页面、必要时提供少量 JSON 接口;核心交互逻辑放前端 JS。
- **把可判定的纯逻辑抽成独立 Python 模块**(如 `xxx_core.py`),用纯函数实现(输入→输出,无副作用),
  以便 `tests/` 下的单元测试能直接 import 并断言。前端 JS 可复刻同一套逻辑。
- 模板放 `templates/`,静态资源放 `static/`。样式写进 `static/css/*.css`,内联 style 不超过约束上限。
- `requirements.txt` 只列必要依赖(flask 及其必需项),不得出现被禁依赖。
- `README.md` 简述功能、如何运行(`pip install -r requirements.txt` + `python app.py`)、端口。

## 硬性要求
1. 产物必须**真的能跑**:`python app.py` 起服务后,首页(通常 `/`)返回 200。
2. **验收标准(TC/AC)会被逐条自动检查**:http_* 会真起服务访问路由、检查状态码/响应体;
   file_exists/text_* 会检查文件是否存在/是否包含指定内容;unit_test 会真的运行对应测试文件并要求通过。
   请确保你产出的文件路径、页面文案、脚本内容、测试都与验收标准**严格对应、真实可跑通**。
3. 单元测试必须能独立跑通(`python -m unittest`),测试针对抽出的纯逻辑模块,覆盖验收标准里点名的行为。
4. 不得使用被禁依赖、不得出现被禁的危险代码调用(见全局硬约束)。
5. 代码整洁、命名清晰、必要处有简短中文注释;不要 TODO、不要占位空实现。

## 输出
严格按下方「输出格式」只输出文件块,输出「必须输出的全部文件」清单里的每一个文件,不多不少。
