# L4 · 确定性(可复现是最硬的验收)

## 讲什么
"通过一次"不够硬。真正可信的验收是:**同样的输入,重跑结果字节一致**。
这一层把"跑到通过"的流程**独立跑两遍**,比对最终产物的 sha256。

## 为什么这是我们的差异点
主流 AI 编码产品几乎都不做这件事(黑盒、带随机性)。而确定性让你能:
- 把"产物哈希"当验收标准写进 CI;
- 复现任意一次历史生成;
- 回归时一眼看出"到底变没变"。

## 怎么做到
- 固定 `temperature=0` + `seed`(在 `lib/model.py` 读环境变量,默认 0 / 42)。
- sample 模式是**纯确定**的;real 模式靠 temp0+seed **逼近**确定(模型侧仍可能有微小抖动,所以要比对+记录)。
- 每次运行追加 `runs.jsonl`,形成可审计基线。

## 组件(相对 L3 新增)
- `determinism.py`:`run_once()` 跑两遍 → 比对哈希。
- `output/l4/runs.jsonl`:确定性基线日志。

## 动手
```bash
python harness-5/l4_determinism/determinism.py
cat harness-5/output/l4/runs.jsonl
```
两次 sha256 相同 → 确定性通过 ✓。

## 到这里

这就是一个**窄而确定**的 Harness + Loop 最小实现,每一块都能当场改。
