# L2 · Loop(自我纠错的闭环)

## 讲什么
把 L1 的"生成 + 验收"接成**闭环**:验收失败 → 把失败报告回喂给模型 → 重新生成 → 再验收,
**直到通过**。这就是 Loop 的本质。

## 关键概念
- **Maker / Checker 分离**:生成的是 Maker,验收的是 Checker;Checker 的输出(失败报告)是 Maker 的下一轮输入。
- **可验证的停止条件**:循环停在"验收全绿",而不是"模型说它写完了"。这是 loop 能自动化的前提。
- **状态可追溯**:每轮结果写入 `state.json`。

## 组件(相对 L1 新增)
- `loop.py`:`while not ok: 生成→验收→回喂`。
- `output/l2/state.json`:逐轮状态。

## 动手
```bash
python harness-5/l2_loop/loop.py
cat harness-5/output/l2/state.json
```
sample 模式下:第 1 轮 BUGGY 失败 → 回喂 → 第 2 轮 CORRECT 通过。

## 观察到的问题(引出 L3)
- L2 是**裸循环,没有任何刹车**。真实模型若一直修不好,会**无限循环、烧光额度**。
- 若两轮产物完全一样(卡住了),它也察觉不到,还在傻转。
- **教学点**:循环必须有护栏——迭代上限、花费上限、卡死检测。→ **L3**。
