## 二、跑一条完整链路（5 分钟）

### 第 1 步 · 输入需求

「我的待办」→ 填两栏 → 【＋ 创建】

| 栏 | 示例 |
|---|---|
| 一句话说清要做什么 | 番茄时钟支持自定义时长 |
| **验收要点** | 两个数字输入框；非法值回退 25/5；不改原有行为 |
| **工作区** | 决定它改哪个仓库、过哪个门禁（pomodoro / cs） |

**工作区是这一版新增的**：需求绑了工作区，起运行时就自动用那个仓库和那个门禁——
不用在页面上再选一次任务。

> 验收要点写不成可判定的句子，后面门禁就写不出来。这是整条链的地基。

### 第 2 步 · 生成 Spec

点该行【Spec】→ 选中需求 → 模式选「统一生成」→ 【▶ 生成 14 份】

跑完你会看到 14 行，带**分组 / 依赖 / 字数 / 状态**。

顺手试一下：点第 3 份的【重生成】——**下面 11 份立刻变红「需修改」**。
因为它们是 DAG 的下游。这是这一页最值得演示的地方。

### 第 3 步 · 审几份（可选）

想让 Spec 参与执行，得先审。点几份【通过】，状态变绿。

### 第 4 步 · 拆 WBS

切到「WBS」→ 选需求 → 【▶ 拆解】→ 8 张卡，每张挂**来源 Spec**。

想演示 Jira 回写：点行尾【回写】→ 拿到 `PROJ-xxxx`；再点一次会被拒（幂等）。

### 第 5 步 · 起运行

切到「执行」：

```
① 「来源需求」下拉 → 选刚才那个需求
② 「任务」下拉 → 番茄钟（决定工作区和门禁）
③ 点【看 prompt】← 先看这个，确认需求真的传下去了
④ 点【▶ 起运行】
```

**第 ③ 步是重点**：那个 prompt 是「需求 + 已审 Spec + WBS 任务 + 工程约定」拼出来的，726 字符。
它就是 agent 这一轮要干的事。

跑起来之后会弹两次审批（写 index.html / 写 app.js），点【通过】。

### 第 6 步 · 看结果

「验收」→ 选番茄钟 → 【▶ 跑门禁】→ 逐条断言出来。

## 三、诚实说三件事

### ① mock 模式不读 prompt

现在默认是 **MOCK 模式**：模型不读你拼的 prompt，只按 `demo/shared/mock/pomodoro.json` 的剧本演。

所以：
- ✅ **链路是真的**——需求 → Spec → WBS → prompt → run，每一步都通
- ❌ **代码不是"按你的需求"写的**——是固定剧本

要让它真按需求写，得：

```bash
# 1. 填 key
vi ../demo/config.env        # DEEPSEEK_API_KEY=sk-...
# 2. 用真实模型起服务
python3 app.py --real
```

### ② 工作区绑上了，但只有两个可用

现在需求可以绑定工作区（pomodoro / cs），起运行时会自动用那个仓库和那个门禁。

新建需求时选 `cs`，跑完你会发现改的是 `fixture/cs/support.py`，
门禁走的是 `check-cs.py`（9 条断言）——**pomodoro 一个字没动**。

但工作区注册表只有这两条（在 `demo/shared/tasks.json`）。
要接真实仓库，加一条就行：

```json
{"id":"my-repo","name":"我的仓库",
 "fixture":"../../my-repo",          // 指向任意目录
 "check":"shared/check-my-repo.py",  // 它自己的门禁
 "task":"shared/tasks-my-repo.md"}
```

### ③ 自由任务受同一份门禁约束

如果你不选需求、直接在需求框里写别的，跑的还是番茄钟的剧本和门禁。
页面上会明确提示这一点。

## 四、现在能做什么、不能做什么

| 能做 | 不能做 |
|---|---|
| 输入需求 → 14 份 Spec（真生成、真 DAG、真失效传播） | 让 agent 按你的需求写任意项目的代码 |
| Spec → 8 张 WBS 卡 → 回写 Jira（桩） | 真实 Jira 双向同步 |
| **需求绑定工作区**（绑 cs 就真改 cs，pomodoro 不受影响） | 工作区只有两个（加一条 JSON 即可扩充） |
| 需求 → prompt → 真跑一轮（mock / 真模型都行） | mock 模式不读 prompt（要真写代码得 `--real`） |
| 审批真的阻塞、门禁真的判定 | 多租户、并发上限、认证 |
