# 使用说明

## 一、启动

```bash
cd /Users/lvzhaobo/code/home/dsh/platform
python3 app.py            # 离线 MOCK 模式（不需要 API key）
python3 app.py --real     # 真实模型（先在 demo/config.env 填 DEEPSEEK_API_KEY）
```

浏览器打开 **http://127.0.0.1:8899**

> 端口默认 8899（8787 常被别的服务占用）。可用 `python3 app.py --port 9000` 改。

界面右上角有个绿点：**已连接** = 后端通了、SSE 也连上了。

## 二、四个页面

### 1. 我的待办

**做什么**：建需求、看全局、一键起运行。

```
① 填「一句话说清要做什么」+「验收要点」+ 选【工作区】→ 点【＋ 创建】
② 列表里出现新需求，状态「待分析」
③ 每行两个按钮：
   [Spec]  → 跳到 Spec 页并选中这个需求
   [起运行] → 跳到执行页并立刻跑
```

**工作区**决定三件事：改哪个仓库、过哪个门禁、跑完产物落在哪。
绑 `cs` 就改 `fixture/cs/support.py`、走 `check-cs.py`；绑 `pomodoro` 就走前端那套。

背后接口：`POST /api/reqs`、`GET /api/reqs`、`GET /api/workspaces`、
`GET /api/approvals`、`GET /api/runs`、`GET /api/gates`

顶部四个数字：需求数 / 待审批 / 运行中 / 最近门禁。

> **待审批 > 0 时，页面会自动弹出审批框**——不用切到执行页。

---

### 2. Spec

**做什么**：把需求拆成 14 份带依赖的 Spec，并逐份审核。

```
① 顶部选一个需求（下拉框）
② 看右上角引擎标记：**引擎：DeepSeek** 或 **引擎：模板**
   （有 key 且非 MOCK → DeepSeek；否则退回模板，秒出但内容空）

③ 选模式：
   统一生成   → 14 份一次生成完，再慢慢审
   分组审     → 每生成一组停一次
   逐份审     → 生成一份就停下等人（会真的阻塞）
④ 点【▶ 生成 14 份】

选 DeepSeek 引擎时，**生成过程是流式的**：进度条上方会出现一个面板，
实时显示正在写哪一份、已写多少字、正文一段段冒出来。

```
┌ 正在生成 S01 · 立项提案与范围说明（第 1/14 份）      940 字 ┐
│ ## 4. 关键决策与假设                                        │
│ | 编号 | 决策/假设 | 说明 |                                  │
│ | D1 | 输入单位为分钟 | ...                                  │
└─────────────────────────────────────────────────────────────┘
```

面板只在下一条开始时自动切换，不会闪。
⑤ 每行三个按钮：
   [通过] [打回] [重生成]
⑤ 点行本身 → 右侧抽屉看全文
```

**最值得演示的一步**：点某一份的【重生成】—— 下面 11 份会自动变红标「需修改」。

因为它们是 DAG 的下游。这一步证明「依赖」列不是装饰。

**DeepSeek 生成 vs 模板生成**：

| | DeepSeek | 模板 |
|---|---|---|
| 字数 | 1,350–2,270 | 160–210 |
| 内容 | 具体到需求的规则、表格、边界 | 「按上游确定」这类空话 |
| 耗时 | 14 份约 2 分钟 | 秒出 |
| 什么时候用 | 真评审、真交给 agent | 讲流程、快速演示 |

每行状态旁边会标 `LLM` 或 `模板`，一眼能看出这份是什么生成的。

背后接口：`POST /api/specs/generate`、`GET /api/specs`、`GET /api/specs/engine`、`GET /api/specs/progress`、
`POST /api/specs/:id/review`、`POST /api/specs/:id/regenerate`

---

### 3. 执行

**做什么**：真的跑一次 agent，看事件流、撞审批。

```
① 选「来源需求」（可选）——选了之后 prompt 由需求 + 已审 Spec + WBS 拼成
② 选任务（决定用哪个工作区 / 哪个门禁）
③ 点【▶ 起运行】—— 想确认它到底要干什么，点【看 prompt】
③ 左边日志会实时滚动：
   [step 1] → list_files(...)
   [step 4] → run_command({"argv":["rm","-rf","src"]})
           ⛔ 被拒：不在白名单
④ 走到写文件时，会弹审批框 → 点【通过】或【拒绝】
⑤ 跑完底部提示「✅ 完成且门禁绿」，KPI 里门禁变绿
```

**关键点**：点【通过】之前，**后端的 agent 线程是挂起的**——不是假装等待，是 `threading.Event` 卡在那里。

一边开着执行页，一边在终端跑 `curl /api/approvals`，能看到那条 pending 一直挂着，直到你点按钮。

**注意 mock 模式的边界**：mock 模型**不读 prompt**，只按 `shared/mock/*.json` 的剧本演。
所以「看 prompt」是让你确认「链路真的把需求传下去了」；要让它真按需求写代码，得 `--real` + 填 key。

背后接口：`POST /api/runs`（带 `req_id` 会自动拼 prompt）、`GET /api/events`（SSE）、`POST /api/approvals/:id`

---

### 4. WBS

**做什么**：把 Spec 拆成任务卡，回写 Jira。

```
① 选需求 → 点【▶ 拆解】
② 每行一张卡：来源 Spec / 估时 / 依赖 / Jira / 状态
③ 点行尾【回写】→ 拿到 Jira key（重复回写会被拒，幂等）
④ 点【↗ 全部回写】一次写完
⑤ 最后一块「Spec 变了 → 哪些卡要重拆」→ 点【↻ 检查】
```

第 ⑤ 步最有用：改过 Spec 之后，**哪些卡旧了一眼就能看出来**。

判定不是看状态，是比时间戳：`spec.generated_at > card.created_at` → 卡就旧了。
比「状态是需修改」更准，因为重新生成的那份状态是 `待审`。

背后接口：`POST /api/wbs/generate`、`GET /api/wbs`、`POST /api/wbs/:id/jira`、
`POST /api/jira/push-all`、`GET /api/wbs/stale`

---

### 5. 约束

**做什么**：扫 `demo/` 里真实的约束文件，按四象限归类 + 冲突检测。

```
① 点【↻ 重新扫描】（进页面会自动扫一次）
② 按四个格子分组列出：文件 / 象限 / 强制性 / 行数 / token
③ 注意 token 列：确定性文件显示 —，因为它们不进上下文
④ 底部是冲突检测结果
```

**为什么这一页值得看**：它读的是**你自己的仓库**，不是假数据。
换掉 `modules/constraints.py` 里的扫描根目录，就能指向任意项目。

背后接口：`GET /api/constraints`、`POST /api/constraints/check`

---

### 6. 验收

**做什么**：把门禁从「一个 exit code」变成「N 条具体断言」。

```
① 选任务
② 点【▶ 跑门禁】
③ 逐条列出：
   1  ❌  存在 work-minutes / break-minutes 两个数字输入框
           没找到 id="work-minutes" 的 input
   3  ✅  按「分钟 × 60」换算成秒
            const w = Number(el.value) * 60 —— 别忘了乘 60
```

每一条都带 **detail 或 hint**，告诉你「哪条没过 / 该怎么改」。

进页面时会自动显示最近一次结果，不用每次重新点。

背后接口：`POST /api/gates/run`、`GET /api/gates/latest`

## 三、三条可复制的演示路径

### 路径 A：完整闭环（约 60 秒）


```
Spec 页 → 生成 14 份 → 点第 3 份的【重生成】
       → 下面 11 份全部变红「需修改」
```

### 路径 C：审批阻塞（20 秒）

```

```

## 四、数据在哪、怎么清

```
data/
├── reqs.json        需求
├── specs.json       Spec（含全文）
├── wbs.json         任务卡
├── gates.json       门禁历史
├── runs.json        运行记录
├── events.jsonl     事件流（仅追加，不随重置清空）
└── sessions/*.jsonl 每次 run 的会话日志
```

都是纯文本，能 `cat`、能 grep、能进 git。

**清空业务数据**：点右上角【重置数据】，或

```bash
curl -X POST http://127.0.0.1:8899/api/admin/reset
```

（事件日志会保留，方便回看）

**同时把 demo 的 fixture 复位**（不然门禁一直是绿的）：

```bash
python3 ../demo/reset.py
```

## 六、常见问题

| 点了「拆解」提示「Spec 还没生成齐」 | 拆解要求至少 5 份 Spec | 先去 Spec 页生成 14 份 |
| 约束页扫到的都是 demo/ 下的文件 | 扫描根目录写死在 `modules/constraints.py` | 改 `DEMO` 常量指向你的项目 |
| 现象 | 原因 | 怎么办 |
|---|---|---|
| 右上角红点「未连接」 | 后端没起 | `python3 app.py`；看终端有没有报错 |
| 端口被占用 | 8787 常被别的服务占 | 用默认 8899，或 `--port 9000` |
| 点了起运行没反应 | 有别的 run 在跑 | 先去执行页【停止】，或等它结束 |
| 门禁一直是绿的 | 上次演示改好了 fixture | `python3 ../demo/reset.py` |
| 审批框弹了但不点，页面卡住 | 正常，后端在等你 | 点【通过】或【拒绝】 |
| 改了 `web/index.html` 没生效 | 浏览器缓存 | 已加 no-store，强制刷新 Cmd+Shift+R |
| 真实模型跑不通 | 没填 key | 先用默认 MOCK 模式 |
