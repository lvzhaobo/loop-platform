## 未完成 / 待改进

### ✅ IMP-01 · 把 Spec 形态链路接进 generate.sh / CI（批量回归）  ·  P0  ·  TODO

**动机**：现在 Spec 形态（如 `pomo_auto`）只能手动三步（compile → run_model → verify_ac）单跑；
需要让它像 catalog 用例一样被 `generate.sh` 批量回归、进 CI 守门。

**现状（已具备的能力，不用改）**：
- `run_model.py` 已按形态分流：有 `case.json` 走 catalog，有 `spec/manifest.json` 走 Spec 形态。
- `generate.sh` 已有验收器分流（第 44–49 行）：`HARNESS_VERIFY_SOURCE=auto` 时，
  该 case 有 `spec/acceptance.json` 就用 `verify_ac.py`，否则用 `verify.py`。

**缺口与具体改造点**：

1. **用例集来源纳入 Spec 用例**
   `generate.sh` 第 20 行 `CASES` 只来自 `constraints.json` 的 `run_cases`/`cases`（全是 catalog）。
   Spec 形态 case（`cases/*/spec/manifest.json` 且无 `case.json`）不会被自动纳入。
   → 方案：在 `constraints.json` 加 `spec_cases` 列表（或自动扫描 `cases/*/spec/manifest.json`），
   合并进 `CASES`；并保留 `HARNESS_CASES` 手动覆盖。

2. **确定性复跑（`HARNESS_DET_CHECK=1`）对 Spec 形态降级**
   第 70–80 行会复跑并比对字节哈希。交互产物是 LLM 生成、非字节确定 → 必然 `drift` 告警，
   且**多烧一次额度**。→ 方案：Spec 形态跳过 det-check（或降级为「只校验再次通过 verify_ac」，
   不比字节）。判定依据：该 case 无 `case.json` / manifest.archetype==spec。

3. **sample 模式下跳过 Spec 用例**
   `run_model.py` 对 Spec 形态在 `HARNESS_MODE=sample` 会 `sys.exit`（交互产物无法模板化确定生成）。
   CI 冒烟常用 sample 省额度 → 批次里遇到 Spec 用例会直接失败。
   → 方案：`generate.sh` 在 `HARNESS_MODE=sample` 时跳过 Spec 形态用例（打印 `SKIP(spec, sample不支持)`），
   不计入失败。

4. **验收来源默认值 / CI 配置**
   catalog 与 spec 混跑时只能用 `HARNESS_VERIFY_SOURCE=auto`（按 case 自适应）。
   → 方案：CI 的 Spec 回归 job 里 `export HARNESS_VERIFY_SOURCE=auto`；本地默认仍保持 `fixed` 不动。

5. **CI 编排**（`harness-4/ci/github-actions.yml`）
   → 方案：新增（或扩展）一个 job：`HARNESS_MODE=real HARNESS_VERIFY_SOURCE=auto`
   跑 Spec 用例集（真实 LLM，需 `DEEPSEEK_API_KEY` secret）。因为烧额度，建议限触发条件
   （手动触发 / 打标签 / 仅 `cases/*/spec/**` 变更时）。

**涉及文件**：`harness-4/generate.sh`、`harness-4/constraints.json`、`harness-4/config.env`、
`harness-4/ci/github-actions.yml`、（可能）`harness-4/tools/run_model.py`。

**完成定义（DoD）**：
- `HARNESS_CASES="pomo_auto" HARNESS_VERIFY_SOURCE=auto bash harness-4/generate.sh` 能跑通并记入 `output/runs.jsonl`；
- catalog 用例默认路径零回归（`blog` 等仍 `fixed` + `verify.py`）；
- sample 批次遇 Spec 用例正确 SKIP，不误判失败；
- Spec 用例不再触发无意义的确定性 drift 告警 / 不多烧额度；
- CI 有一个可手动触发的 Spec 回归 job。

### IMP-02 · ECS 部署固化为脚本 / 常驻服务  ·  P1  ·  TODO

**动机**：当前 `pomo_auto` 上 5300 是手动 `tar-over-ssh + PORT=5300 nohup`（一次性 askpass）。
应沉淀成可复用入口，避免每次手敲。

**方案（二选一或都做）**：
- `harness-4/tools/deploy_spec.sh <case> <port>`：封装 tar-over-ssh + 拉起 + 本机 curl 自测 + 公网探活；
- 或走正式 CI 通道：把 Spec 产物作为 `sampleN` 推 loop-sample 公开仓，复用 `ci/loop-sample-deploy.yml`（端口 1000+N，git 拉取式、systemd 自拉起）。

**完成定义**：一条命令把任意 Spec 用例部署到指定端口并回报 HTTP 状态。
